# 升级到 Anas 4.x：数据影响与手动恢复

[English](UPGRADE_TO_4.en.md) · [用户手册](USER_GUIDE.zh-CN.md)

**从 4.0 之前的版本升级到任意 4.x 版本，旧对话记录及全部长期记忆（含项目记忆）不再可用，程序不提供迁移或旧版备份导入。** 这是 4.0.0 引入的数据目录变更，直接跳过 4.0.0 升级到后续 4.x 也会受到影响；已使用新布局的 4.x 数据不会因这项变更再次丢弃。

本文只说明 4.0.0 的数据目录调整。后续版本的其他兼容性变更，例如插件安装目录调整，以对应发布说明为准。

## 哪些数据受影响

| 数据 | 升级后的情况 | 恢复方式 |
| --- | --- | --- |
| 旧对话记录及其附件、文件修改恢复材料等 | 新版不读取旧会话存储 | 不提供迁移；移动或重命名旧数据库不能恢复对话 |
| 全部长期记忆，包括项目记忆 | 新版使用新的记忆存储 | 不提供迁移 |
| 项目定义和项目设置 | 旧项目不显示，新版读取 `db/projects.json` | 可手动移动原文件 |
| 输入历史，包括置顶输入 | 旧历史不显示，新版读取 `db/input_history.json` | 可手动移动原文件 |
| 插件独立数据 | 旧 `plugins_data/` 不读取 | 可整体移动到 `db/plugins/` |
| 自定义头像 | 旧根目录 `assets/` 不读取，未恢复时使用默认头像 | 可整体移动到 `config/assets/` |
| 全局配置、项目源文件、用户管理的技能和工具等包 | 不因本次目录调整丢弃；全局配置继续读取受支持的 v0 格式 | 无须按本文移动 |

旧文件仍可能留在磁盘上，升级不会自动删除它们，但新版不会读取旧布局，也不会把这些残留纳入新备份。因此“界面中看不到”不等于旧文件已经被删除；保留旧文件也不代表新版能恢复旧对话和记忆。

## 升级前备份

完全退出 Anas 后，将整个旧数据目录另行复制到安全位置，保留在数据目录之外。不要只依赖升级后生成的应用备份，它不包含旧布局残留。

标准 Anas 的默认数据根目录为 `~/.galeAnas/`（Windows 通常为 `%USERPROFILE%\.galeAnas\`）。重命名程序或使用 `--data-dir` 时，以实际使用的数据目录为准。下文所有路径均相对于这个数据根目录。

4.0 之前生成的应用备份 ZIP 不能通过 4.x 的“恢复备份”导入。保留旧备份作为原始资料，不要通过修改版本标记强行导入。

## 手动恢复可保留的数据

建议在新版创建项目或其他新数据前操作：

1. 完全退出 Anas，备份原数据，以及新目录中已经生成的同名文件或目录。
2. 按下表移动需要恢复的文件或目录；目标父目录不存在时先创建。文件内容与目录内部结构不修改。
3. 如果目标已经存在，先将它移到另一处保留，再用旧数据替换。**替换不会自动合并，新版中对应的新数据会被替代。**
4. 重新启动 Anas，核对项目设置、输入历史、插件数据和头像是否符合预期。

| 原路径 | 新路径 | 恢复内容 |
| --- | --- | --- |
| `projects.json` | `db/projects.json` | 项目定义和项目设置；不恢复项目的旧对话或记忆 |
| `input_history.json` | `db/input_history.json` | 输入历史和置顶输入 |
| `plugins_data/` | `db/plugins/` | 插件独立数据，整体替换，不合并 |
| `assets/` | `config/assets/` | 自定义头像资源，整体替换，不合并 |

项目和输入历史沿用受支持的 v0 文件格式，不需要编辑 JSON 内容。不要将旧 `sqlite/`、会话目录或数据库直接搬入 `db/`；本文的移动方法不能恢复旧对话和记忆。

## 什么时候清理旧文件

先完成备份和需要的手动恢复，再进入“设置 → 通用 → 数据清理 → 未知文件”检查预览。该项默认不勾选；清理旧目录会删除其中的全部文件。数据根目录内保存的备份 ZIP 也可能进入清理预览，应先移到其他位置保留。
