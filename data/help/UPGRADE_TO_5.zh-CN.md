# 升级到 Anas 5.x：数据影响与配置复制

[English](UPGRADE_TO_5.en.md) · [用户手册](USER_GUIDE.zh-CN.md)

**当前格式为 catalog v2、会话 v3、独立记忆 v1，项目与对话按项目目录保存。** 当前格式自身的备份、修复和崩溃恢复功能保留。以下按版本说明历史兼容边界；已有当前格式数据无需因这些历史调整再次重置。

**从 4.x 或更早版本升级：** 5.0 起使用全新的原生执行数据库，不迁移旧框架的对话、记忆和运行记录，也不恢复其整包备份。仅可按下方步骤手动复制兼容配置与扩展资源，不复制旧 `db/`。

## 升级到 5.2.0：活动显示重构

本次重构使用全新会话数据库 **v3**。升级前的 v1／v2 对话需要由用户清空，不自动迁移或删除；含会话 v1／v2 的备份不能恢复。配置、项目定义、Skills、工具、插件和独立记忆库保持原格式。请保留需要的旧数据备份，不要手改数据库版本号。新格式支持自身的备份、保全和显式修复。

## 升级到 5.0.2

项目改为 `db/projects/<项目ID>/project.json`，对话放在该项目的 `conversations/` 中。旧 `db/projects.json`／`db/conversations/` 布局不读取、不迁移，其备份不能恢复。仍使用旧布局时，需要先保全数据，再重置全部项目与会话；程序不自动清理旧文件，不要直接搬移旧会话目录。

## 升级到 5.0.1：catalog 权限约束

catalog 从 v1 调整为 v2；当时会话库仍为 v1，当前已按上方 5.2.0 边界改为 v3。含旧 catalog 的备份不能直接恢复。启动提示 catalog 版本或权限字段约束错误时，可在恢复页面选择修复项目数据；程序先保全原文件，再抢救和重建目录索引，无效权限值使用默认智能审核。此操作不转换旧会话格式或重放工具操作，也不能代替项目布局和会话版本的升级处理。不要仅手改版本号。

## 子 Agent 配置兼容性

**子 Agent 配置提醒（4.0.5 起）：** `config/subagents.json` 使用 v1，不兼容、不迁移原 v0 数组配置；旧文件保留并在启动时提示错误，含旧格式的备份不能直接恢复。请完全退出应用，把旧文件移到数据目录之外保留，再启动并重新创建或导入子 Agent 包。不要只修改版本号。已有 v1 配置不受影响。[子 Agent 使用与处理说明](USER_GUIDE.zh-CN.md#子-agent)

## 手动复制步骤

以下适用于从旧框架版本创建新的 5.x 数据目录。默认目录为用户目录下的 `.anas/`：Windows 通常为 `C:\Users\<用户名>\.anas`，可在文件资源管理器地址栏输入 `%USERPROFILE%\.anas`；macOS／Linux 为 `~/.anas/`。旧目录为同一用户目录下的 `.galeAnas/`。程序不会自动导入；使用 `--data-dir` 时以指定目录为准。

1. 完全退出新旧 Anas，先完整备份旧目录并保留原件，为 5.x 准备新的数据目录。已有目标数据须另行备份，不合并或直接覆盖。
2. 按原相对路径复制受支持的 `config/`（含头像 `config/assets/`）、`.env`，以及用户管理的 `skills/`、`tools/`、`subagents/` 和 `plugins/`。子 Agent 管理配置须为 v1；旧 v0 数组按上方说明重新创建。引用的外部目录、程序和项目源码需仍可访问。
3. **不要复制旧 `db/`，不要恢复旧版整包备份。** 旧对话、记忆和运行记录不转换；项目和其他数据库内容从新目录重新建立。复制插件代码不包含旧 `db/plugins/` 中的业务数据。
4. 启动 5.x，核对配置、模型和扩展资源，再重新建立项目。遇到错误时保留原目录和备份，不要修改数据库版本号强行使用。

跨入 4.x 的历史数据影响见 [4.x 升级数据说明](UPGRADE_TO_4.zh-CN.md)；其中的数据库内容恢复方法不适用于 5.x。
