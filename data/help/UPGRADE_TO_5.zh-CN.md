# 升级到 Anas 5.0：数据影响与配置复制

[English](UPGRADE_TO_5.en.md) · [用户手册](USER_GUIDE.zh-CN.md)

**5.0 使用全新的原生执行数据库（catalog v2、会话 v1），不迁移旧对话、记忆和运行记录，也不恢复旧版整包备份。** 仅可手动复制兼容配置与扩展资源；当前 5.0 数据的备份、修复和崩溃恢复功能保留。

**从 5.0.0 升级到 5.0.1：** catalog 从 v1 调整为 v2，会话库仍为 v1。含旧 catalog 的备份不能直接恢复；建议在原数据目录完成修复后重新备份。如果启动提示 catalog 版本或权限字段约束错误，请在恢复页面选择修复项目数据。程序先保全原文件，再修复目录索引；无效权限值使用默认智能审核。此操作不转换旧框架执行库，也不重放工具操作。不要仅手改版本号。

## 升级到 5.0.2

需要重置全部项目与会话。

## 子 Agent 配置兼容性

**子 Agent 配置提醒（4.0.5 起）：** `config/subagents.json` 使用 v1，不兼容、不迁移原 v0 数组配置；旧文件保留并在启动时提示错误，含旧格式的备份不能直接恢复。请完全退出应用，把旧文件移到数据目录之外保留，再启动并重新创建或导入子 Agent 包。不要只修改版本号。已有 v1 配置不受影响。[子 Agent 使用与处理说明](USER_GUIDE.zh-CN.md#子-agent)

## 手动复制步骤

**兼容配置与扩展资源复制：** 5.0 默认使用用户目录下的 `.anas/`。Windows 通常为 `C:\Users\<用户名>\.anas`，可在文件资源管理器地址栏输入 `%USERPROFILE%\.anas`；macOS／Linux 为 `~/.anas/`。旧目录为同一用户目录下的 `.galeAnas/`。程序不会自动导入；使用 `--data-dir` 时以指定目录为准。

1. 完全退出新旧 Anas，先完整备份旧目录并保留原件，为 5.0 准备新的数据目录。已有目标数据须另行备份，不合并或直接覆盖。
2. 按原相对路径复制受支持的 `config/`（含头像 `config/assets/`）、`.env`，以及用户管理的 `skills/`、`tools/`、`subagents/` 和 `plugins/`。子 Agent 管理配置须为 v1；旧 v0 数组按上方说明重新创建。引用的外部目录、程序和项目源码需仍可访问。
3. **不要复制旧 `db/`，不要恢复旧版整包备份。** 旧对话、记忆和运行记录不转换；项目和其他数据库内容从新目录重新建立。复制插件代码不包含旧 `db/plugins/` 中的业务数据。
4. 启动 5.0，核对配置、模型和扩展资源，再重新建立项目。遇到错误时保留原目录和备份，不要修改数据库版本号强行使用。

跨入 4.x 的历史数据影响见 [4.x 升级数据说明](UPGRADE_TO_4.zh-CN.md)；其中的数据库内容恢复方法不适用于 5.0。
