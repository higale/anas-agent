# 数据清理

“设置 → 通用 → 数据清理”只隐藏已确认没有可清理内容的项目。空文件、空子目录仍算有内容；读取失败或尚未完成统计时不据此隐藏。输入历史只判断未置顶条目，会话保留现有置顶、运行和审批保护。

## 未知文件白名单

唯一规则来源为 [dataCleanupAllowlist.json](../src/main/dataCleanupAllowlist.json)，程序直接读取这份文件，不另维护一份路径清单。新增持久化路径时同步更新规则和行为测试。

- 路径相对于数据根目录，使用 `/`；`*` 仅匹配一个路径段内的字符。
- `file` 保留指定文件；`directory` 保留容器本身，继续检查子项；`tree` 保留整个目录树。
- `cache/` 整体保留，由缓存清理处理；`db/conversations/` 整体保留，由对话删除处理。不按数据库登记情况推断其中的文件可丢弃。
- 插件独立数据、用户包及恢复材料按规则保留。文件损坏、格式不支持、插件已卸载不改变已知路径的归属。
- 备份不在白名单内。数据根目录中的 ZIP 及其他未知文件、旧布局目录均可进入清理预览。

“未知文件”默认不勾选。展开可查看待删除的相对路径，目录以 `/` 结尾；清理未知目录会删除其整棵目录树。执行时重新检查白名单，只处理预览与当前候选的交集；预览后新增的顶层候选留待下一次确认。清理不跟随符号链接或目录联接，未知链接只删除链接本身。

未知文件清理与备份、数据结构变更使用同一独占边界；失败项报告错误，不将部分成功当作全部成功。清理不迁移、不恢复旧数据，也不在启动时自动执行。

## 备份默认位置

未配置备份目录时，保存对话框使用系统当前用户的“文档”目录。已经保存的用户选择保持有效，不自动移动原备份。若仍将备份存放在数据根目录，它同样会进入未知文件清理预览。
