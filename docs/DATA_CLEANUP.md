# 数据清理

“设置 → 通用 → 数据清理”只隐藏已确认没有可清理内容的项目。空文件、空子目录仍算有内容；读取失败或尚未完成统计时不据此隐藏。输入历史只判断未置顶条目，会话保留现有置顶、运行和审批保护。

日志清理保留日志目录本身，删除前复核目录身份及实际路径。日志根目录为链接或清理过程中被替换时报告失败，不跟随链接，也不触发日志保留期清理；正常日志目录中的链接只删除链接本身。

自动日志保留期清理跳过链接目录。临时目录及其外部下载登记目录在遍历和删除前复核身份，目录链接或中途替换不会引向外部内容；开发者 HTTP 记录清理同时检查父目录。退出时复用同一临时清理实现，在释放实例锁前完成，并受现有关闭时限约束；超时残留留待下次启动处理，不派生退出后仍可能清理新会话文件的后台进程。

## 未知文件白名单

唯一规则来源为 [dataCleanupAllowlist.json](../src/main/dataCleanupAllowlist.json)，程序直接读取这份文件，不另维护一份路径清单。新增持久化路径时同步更新规则和行为测试。

- 路径相对于数据根目录，使用 `/`；`*` 仅匹配一个路径段内的字符。
- `file` 保留指定文件；`directory` 保留容器本身，继续检查子项；`tree` 保留整个目录树。
- `cache/` 整体保留，由缓存清理处理；`db/projects/` 整体保留，项目定义由项目操作处理，会话资源由对话删除处理。不按数据库登记情况推断其中的文件可丢弃。
- `runtimes/` 保留旧版释放的 Python 和用户安装的依赖。应用不再创建或读取此目录。缓存清理、未知文件清理及备份恢复均保留其内容，备份及修复保全副本跳过此目录。
- 插件独立数据、用户包及恢复材料按规则保留。文件损坏、格式不支持、插件已卸载不改变已知路径的归属。
- 旧 `_system`、`examples/`、`help/`、内置语言副本及 `.examples.mirror.tmp`、`.examples.mirror.previous` 暂存材料继续保留；应用不再释放或刷新这些内容，未知文件清理也不自动删除它们。`lang/` 仍用于用户语言包。当前包内资源不属于用户数据清理范围。
- 备份不在白名单内。数据根目录中的 ZIP 及其他未知文件、旧布局目录均可进入清理预览。

“未知文件”默认不勾选。展开可查看待删除的相对路径，目录以 `/` 结尾；清理未知目录会删除其整棵目录树。执行时重新检查白名单，只处理预览与当前候选的交集；预览后新增的顶层候选留待下一次确认。清理不跟随符号链接或目录联接，未知链接只删除链接本身。

未知文件清理与备份、数据结构变更使用同一独占边界；失败项报告错误，不将部分成功当作全部成功。清理不迁移、不恢复旧数据，也不在启动时自动执行。

## 记忆清理

记忆项统计后台偏好正文和整理任务历史。清理会取消当前整理，清空全局／项目 `MEMORY.md` 和任务记录，并将各对话的处理边界推进到清理时的末尾，避免同一历史消息立即重建内容。旧 catalog 记忆表不参与统计或清理；独立 `db/memory.sqlite` 继续保存处理进度。

## 备份默认位置

未配置备份目录时，保存对话框使用系统当前用户“文档”目录下的 `Anas/backups/`。已经保存的用户选择保持有效，不自动移动原备份。若仍将备份存放在数据根目录，它同样会进入未知文件清理预览。

异常修复或重置前的原始副本保存到系统“文档”目录下的 `Anas/recovery/<UTC时间戳Z-随机后缀>/`；导入备份前自动保存的 ZIP 位于 `Anas/backups/before-restore/<UTC时间戳Z-随机后缀>/`。新路径必须位于活动数据目录之外，保存失败则停止修改，不回退到临时目录。旧位置的副本原地保留。事务暂存与崩溃回滚目录仍位于数据目录旁，不属于长期保全副本。
