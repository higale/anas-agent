# 原生执行与持久状态

实际产品使用原生协调器、宿主和 v1 存储。5.0 使用全新数据库；当前范围见 [HANDOFF](HANDOFF.md)。

## 执行边界

一次完整运行及其持久会话共用一个执行入口。普通聊天、简单聊天、审核、手动压缩、子 Agent 共用同一循环，区别是请求准备和允许的业务能力。

执行内核只接收应用消息、已保存意图、模型请求／响应和工具服务，不依赖 Electron、React 或供应商 SDK。平台装配负责配置、项目目录、模型传输和实际工具。现有 `RunExecution`／`RunObserver` 继续区分执行与观察，观察失败不能回滚已经完成的持久提交。

宿主发布完成或待审批结果时，界面快照读取失败只记录诊断，仍发布持久结果；待审批事件直接携带执行所有者保存的审批请求，界面可再次读取快照。实例释放和渲染器通知失败也不能改写已提交结果，宿主仍完成所属资源收尾并释放运行。

恢复装配的普通错误保留当前执行状态，可修正配置后重试；明确的模型选择错误或准备期间模型持续变化会结束已接受运行，保留其已完成结果，允许下一轮重新选择模型。尚未接受的输入继续保留，重试只接受一次；取消意图优先于错误分类。

后台清理报告写入失败不阻止取消和排空；实时事件保留本次报告及写入错误。没有活跃清理所有者时，持久的“清理中”记录在快照与分页中显示为“结果未确认”，保留原始证据，不伪报清理完成。清理未置顶会话只检查已有运行时，不为判断是否空闲创建执行者；运行中、待审批、资源尚未释放或后台结果未确认的会话继续保留。

## 持久事实

| 事实 | 所有者与要求 |
| --- | --- |
| 会话历史 | 一份有序消息引用，正文内容寻址。消息 ID 与正文版本分开；原始协议输出、工具调用、完整结果、附件、审核范围和应用元数据完整保存。活动文本、推理与推理摘要直接读取所属消息正文，工具调用轮次和子任务也不依赖主消息列表补齐。活动正文的运行归属取自持久载荷记录，不要求正文重复携带运行 ID；若正文明确声明冲突归属则报错。显示投影不作为模型输入或执行身份。 |
| 运行 | 原运行记录持有状态、已保存输入／恢复意图和执行进度。运行进度不是 UI 活动推断，不另造内存权威副本。 |
| 模型批次 | 模型完整响应及其工具调用先提交，再开始工具预检。流式文本和参数只是观察；不完整响应不能生成可执行批次。 |
| 工具调用 | 绑定所属响应、批内序号、供应商调用 ID、原始参数及应用调用身份；通过预检后再计算效果参数摘要。供应商 ID 可能重复或缺失，不能单独作为全局主键。调用结果逐项持久，恢复跳过已有结果。活动索引、实时事件、审批卡片与追加指令位置使用应用调用 ID，供应商 ID 仅用于协议往返。 |
| 效果日志 | 继续保存准备、外部效果意图、结果、重试次数和不确定性确认序数。一次调用只有一个效果身份；普通审批与不确定效果恢复分别记录。日志随所属运行保留；已采纳结果与历史共享正文。终态不再派发，历史删除按运行归属清理日志与无引用正文，文件恢复材料先独立交给保留／清理事务。 |
| 审批 | 保存具体调用及目标、请求载荷、代次和待处理决定。消费决定与对应调用进度一起提交；代次变化后旧决定不可用。 |
| 摘要与规则 | 原始历史不因压缩被替换。摘要只有在 ID、正文及边界匹配时激活；规则、Shell 和文件授权凭据绑定实际请求和调用参数。 |
| 后台任务 | 现有受管调用及子会话继续是任务所有者。父运行只保存监督关系；确认结果来自配对的持久读取，页面移动、隐藏或独立窗口不复制任务。 |

应用数据字段使用 snake_case，TypeScript 使用 camelCase，边界显式转换。供应商原始载荷保留其协议字段，不混入应用状态字段。非 JSON 附件值必须显式编码，至少保留当前已支持的 Map、Set、Uint8Array、日期、正则和错误数据；不让任意业务 JSON 被误识别成内部存储标记。

`runtime/conversationMessage.ts` 定义应用消息数据，`providers/conversationInput.ts` 由它生成三种模型协议的请求；实际模型发送与容量估算已使用该路径。完整内容、调用、原生回放、artifact 和应用上下文分别保存，显示块只是派生结果。原生产品使用执行版本 v1。

当前编码用无歧义的结构保存类型，分别验证普通对象与类型值的往返，不将普通业务 JSON 误识别成内部标记。

## 运行循环

以下阶段由协调器推进，不要求逐阶段增加数据表。仅在影响恢复决策或外部效果时保存进度。

1. **接收已保存意图。** 核对运行归属和当前会话修订；消费用户输入、重生成或压缩请求。输入消息、运行开始和意图确认在同一提交中完成。恢复从已有进度继续，不能再次追加相同输入。
2. **准备请求。** 重新解析当前模型及参数，选择工具，应用附件、记忆、项目规则、摘要、简单聊天或审核投影，计算容量及有效服务端用量校准。异步准备期间配置改变时重新准备；已收到的模型结果不因事后配置变化而丢弃。
3. **调用模型。** 复用现有原生协议、流聚合和应用重试。完整响应、用量、请求身份与逻辑调用计数一起提交。工具调用先保留原始解析参数（包括非对象值和 JSON 数字溢出后的非有限值）；协议 JSON 解析失败、调用身份缺失或响应不完整时，在接纳前报告协议错误。没有工具调用时进入结束判断；审核必须有经过范围校验的报告，普通文本不冒充报告。
4. **预检批次。** 参数、规划冲突、规则、Shell／补丁目标和普通审批按现有行为处理。非对象参数、非有限数字和模型可以修正的 schema／业务输入错误保存为对应工具结果，随下一次请求交给模型纠正；原始参数不被空对象或 null 替代；响应与执行调用按原值核对，不使用效果 JSON 规范化作为保存前置条件。错误调用不进入授权和效果派发，效果摘要仍只接受有限数字。未保存纠错结果的非对象参数不能被标为已预检；取消、存储失败和普通运行故障不伪装成输入错误。路径规范化后的实际参数与批准凭据一起保存。
5. **等待决定或派发工具。** 需要决定时先保存审批再结束本次执行调用；恢复核对已保存代次。批准不自动授权同批其他调用，拒绝保留原整批未回答调用处理。实际派发仍使用原生能力、访问模式和效果日志，不绕过受管服务。
6. **保存与收尾批次。** 并行调用每个结果独立持久；一项失败仍等待其他已进入调用和清理结束。不确定效果保留确认请求，已保存结果直接恢复。整批结果落定后追加排队指令及附件，再准备下一次模型请求。

启动恢复根据已提交的应用状态分类。已保存但尚未开始的输入可供显式继续；输入缺失或归属不一致明确报错。已完成、失败或取消的运行不重新派发，未回答的审批继续等待。

子任务的执行状态和祖先活动投影分开提交：审批答复先保存，由执行内核核对代次并消费；祖先活动更新失败时保留已接受的决定和原生执行状态，投影事务整体回滚，随后从权威状态重建。已消费的审批和已完成工具操作不因活动投影失败而撤销或重放。启动恢复也可补齐已结束后代的祖先投影，保留既有排序与时间；仍在运行的祖先不会因此被取消。

子任务恢复失败信息在只读核对期间保留，只在实际重新开始执行时清除。没有活跃执行者时，等待立即返回当前状态；停止等待与取消子任务仍是独立操作。已完成子任务的结果正文损坏时明确报告读取失败并保留原始证据，修复正文后可重新核对。原生消息、活动正文引用及终态同事务保存。

宿主等待不会取消已登记的后台任务。效果边界必须匹配同一运行、会话和受管调用，允许已转后台的 preparing／running 调用在容量释放后继续；已完成、未转后台或归属不符的记录不能取得该例外。审批消费与效果重试在同一事务内校验代次并推进。

文件事务经真实宿主结束运行后执行原有清理流程：完整修改前后内容先归档到文件变更账本，再删除可清理的临时事务文件；未解决冲突的原始备份与证据继续保留。硬崩溃验收同时核对归档内容、操作身份和文件身份。

撤销运行结束或历史被删除时，两侧材料交给文件事务层根据持久证据清理：已完成撤销不会因尚未保存工具结果而被永久强制保留，部分完成的逆操作、冲突或缺失证据仍保留。活跃运行仍须采纳精确结果才交接；普通未采纳写入继续强制保留。当前格式使用同一交接，不以清理完成伪造工具成功，也不重复覆盖后续用户修改。
7. **结束运行。** 确认后台监督要求及运行结果，原子提交终态。后续活动、摘要或 UI 投影失败只记录诊断并允许重建，不把已完成运行改成失败。取消在已确认提交之后发生时不能撤销该提交。

手动压缩走同一运行入口，生成并暂存摘要后只提交摘要和完成事实，不额外调用普通聊天模型。模型调用上限沿用主 Agent、子 Agent、恢复和零值语义。请求预览使用同一准备及协议编码流程，但不产生运行、工具副作用或实际网络请求。

历史编辑或重生成先提交历史与资源引用变更，再通知文件变更区刷新，最后处理可重试的物理清理。通知失败只记录诊断，不使已提交操作丢失编辑草稿；附件／文件清理失败保留持久意图，不能阻塞已提交历史的显示更新。

## 数据兼容边界

5.0 经用户批准使用全新执行数据库 v1。只复制兼容配置和扩展资源，不复制旧 `db/` 或恢复旧版整包备份。启动检查保留原文件，拒绝旧执行版本和缺失 catalog 的残留会话；不转换或重放旧执行状态。

当前格式的运行恢复、备份和手动修复继续保留。修复先保全源文件，按当前结构校验，独立数据分别抢救；不把不支持的旧结构改个版本号冒充当前结构。当前备份在暂存目录通过完整校验后才替换，事务失败或进程退出后可回滚。

## 验收门槛

- 原生消息、完整结果、身份、引用、审批代次和下一次行为须有集成检查；恢复不能重复工具、子 Agent 创建或用户输入。
- 注入结果保存、审批消费和数据替换的失败边界，验证重复启动、当前备份恢复、部分修复、未知版本拒绝及回滚。
- 旧格式仅保留最少的拒绝样本；当前格式修复样本见[存储回归样本](../src/main/agent/fixtures/storage/README.md)。
- 平台、真实服务和发布验收分别记录，不以脚本模型测试代替真实供应商验证。
