# 自定义工具

自定义工具把固定命令和 JSON 参数 Schema 包装成模型可调用的能力。在“设置 → 工具”管理定义及全局启用状态。新项目默认启用全部可用工具，项目和子 Agent 按工具勾选。界面不生成业务脚本或安装依赖。

## 目录与选择

工具从以下来源发现：

- 外加目录：在全局工具页“添加目录”，直接引用所选目录下的工具包，不复制文件。
- 用户工具：应用数据目录的 `tools/<目录>/TOOL.json`，在全局工具页管理。
- 项目工具：点击项目设置“能力 > 自定义工具”标题旁的加号添加总目录，各目录以“项目 - 目录名”与其他来源并列显示，读取其子目录中的 `TOOL.json`，仅对当前项目生效，不进入全局工具管理列表。添加、打开目录及移除引用与项目技能共用交互；空目录和失效引用保留。添加或移除随项目保存，取消不生效，移除不删除文件。不再自动发现源文件夹的 `.agents/tools/`；原目录可手动添加，并在能力列表中核对勾选。
- 子 Agent 私有工具：Agent 包中的 `tools/<目录>/TOOL.json`，仅所属 Agent 可用，不进入全局工具列表；能力开关与项目限制见[子 Agent](../data/help/USER_GUIDE.zh-CN.md#子-agent)。

系统自定义工具直接从程序包 `data/tools/<目录>/TOOL.json` 加载，可启停、浏览，导入后得到可独立编辑的副本。用户数据中的 `tools/_system` 仍按普通工具目录处理，旧系统工具选择在对应 ID 缺失时仍可取消。

项目及外加来源不能占用程序包资源目录、其父目录或目录别名，包括技能内附的工具模板。已有此类引用保留配置并显示不可用，不允许借此新增、改名或删除包内内容。文件编辑按实际目标检查，指向包内文件的链接只读；先导入为独立用户副本后可正常编辑。

`config/tools.json` 保存格式版本、排序、全局停用工具名单和外加目录，定义保存在工具包中。读取和校验只接受当前格式，未配置的可选字段使用默认值。工具配置和 `TOOL.json` 均以显式 `version: 0` 为当前格式；无版本及旧编号数据不再迁移，当前没有升级模块。文件变化后可刷新，每次新运行重新读取目录。工具页上方为“内置工具”和“MCP”，下方为全部自定义工具、系统、用户及外加目录。目录树支持展开文件和语法高亮预览；工具的 UTF-8 文本文件支持编辑、保存和取消，保存检查外部修改冲突并保留脚本权限。直接编辑 `TOOL.json` 不能更改工具 ID。用户和外加目录中的工具支持新增、编辑、删除、导入、排序和打开目录；新增和导入写入所选来源，删除将整个工具包目录移到废纸篓。改名会同步修改目录名，保留 ID、选择和排序；目标已存在时拒绝，保存失败回滚。运行中的工具目录不能改名或删除。

外加目录可改显示名称、排序和移除；移除仅解除引用，不删除文件。外加工具的定义和文件编辑直接保存到来源目录。项目来源只在项目设置中展示，不进入全局工具页。项目工具目录以“项目 - 目录名”与其他来源并列显示，添加目录按钮位于“自定义工具”标题旁。仅顶层“自定义工具”可折叠，内部来源和目录直接显示；条目使用普通复选框，一行多个，不带装饰图标。已停用、加载失败、同名覆盖或需要后台工具等状态使用警示色显示，具体原因放在条目 tooltip 中，勾选不绕过运行限制。

Markdown 文件默认显示排版预览，可切换源码；顶部元数据折叠展示。相对图片按文件所在目录解析，本页链接跳转标题，其他本地文件链接在文件管理器中定位。

项目直接使用保存的工具选择，新项目默认为全部已启用工具。子 Agent 使用自身选择，可勾选“使用当前项目工具”；启用“限制子 Agent 能力”后还需与项目有效范围取交集。

同名工具从有效选择中按项目工具目录顺序、用户目录、外加目录、程序包系统目录的优先级选取；同一来源按保存的顺序选择。高优先项未启用或加载失败时使用下一个，其他项显示覆盖来源。缺失或无效工具保留可取消的能力引用，一个坏包不阻断其他工具。

## 工具包格式

包中可包含 `scripts/`、`README.md` 和资源文件。`TOOL.json` 是 Anas 工具格式，与标准 Agent Skills 的 `SKILL.md` 分开：

```json
{
  "version": 0,
  "id": "submit-result",
  "name": "submit_result",
  "description": "校验结果标题。",
  "input_schema": {
    "type": "object",
    "properties": { "title": { "type": "string" } },
    "required": ["title"],
    "additionalProperties": false
  },
  "command": "\"{{tool_dir}}/scripts/submit.py\" --mode validate --data {{args}} --verbose",
  "timeout_seconds": 0,
  "interactive": false
}
```

- `id`：1–100 个字母、数字、下划线或连字符，同一来源内唯一。界面新增时自动生成，手动改名或移动目录时应保留。
- `name`：模型可见名称，最多 64 个字符，以字母或下划线开头，其余只用字母、数字、下划线或连字符；不能占用内置、Shell 或 MCP 等保留名称。
- `input_schema`：JSON Schema **2019-09**，根类型必须为 `object`。省略 `$schema` 也使用该版本，声明其他版本会被拒绝；保存和实际执行使用相同校验版本。
- `timeout_seconds`：`0` 表示不限时，正整数表示执行期限，最大 2,147,483 秒；界面留空保存为 `0`。
- `interactive`：是否在启动时分配 PTY，默认 `false`。

`TOOL.json` 最多 128 KiB，每个来源目录最多 2048 个条目。字段校验和命令语法见 [customTools.ts](../src/shared/customTools.ts)，目录发现及导入见 [toolsStore.ts](../src/main/toolsStore.ts)。

## 参数编辑

详情页的“编辑信息”和“编辑参数”打开同一个编辑窗口，分别进入“基本信息”和“参数”页；切换页签保留草稿。参数页支持“参数 / 源码”切换，可增删改参数名、类型、必填、描述和常用约束，展开对象或数组继续编辑子参数。单个参数在窗口内编辑，应用后返回参数列表；整份草稿在保存工具时写入，放弃修改需确认，不改动脚本。

未编辑的 Schema 关键字保留。引用、组合类型和元组等复杂定义使用源码编辑；涉及引用或高级约束的改名、删除需在源码中同步处理。改名、删除会同步当前对象的 `required` 和 `dependentRequired`。`default` 与 `format` 仅作标注，不自动补入默认值或增加格式校验。

## 命令与参数

命令是一个程序及固定参数，必须包含且只包含一个独立的 `{{args}}` 参数。运行时先解析参数，再将它替换为模型提交的完整 JSON 字符串，直接启动进程；JSON 中的引号、换行和 Shell 符号不会被再次解析。JSON 参数最多 1 MiB，同时受系统命令行长度限制，大段内容应通过文件传递。

工作目录始终是 `TOOL.json` 所在目录，相对脚本和资源路径从这里解析，例如 `scripts/run.py {{args}}`。`{{tool_dir}}` 在分词后替换，含空格的目录仍为单个参数；访问项目文件应传入明确路径。

命令首项 `{{bundled_python}}` 固定使用程序包解释器。该命令的 `ANAS_CACHE_DIR` 指向当前数据目录下的缓存。文档工具从 `python/anas-documents/` 加载转换模块。`input_path` 和 `output_path` 均为必填绝对路径，分别指定源文档和新 Markdown 文件。工具按需创建父目录，成功后返回转换标记、两个路径、行数和字节数。 嵌入图片导出到同级的 `<输出文件主名>_images/`，Markdown 使用相对路径引用图片。

详情页中可识别的包内脚本路径显示为彩色链接，点击展开左侧目录并选中文件。文件缺失时，用户或外加目录中的工具可确认创建空文件及缺失目录；已有文件不会被覆盖。

命令语法：

- 空格和换行分隔参数，单引号或双引号包围含空格的参数；相邻引号片段会合并，如 `--label="daily report"`。
- 反斜杠始终为字面字符，包括 `--output "C:\data\"` 中目录末尾的 `\`。要包含双引号，用单引号包围，反之亦然。
- 引号内的 `$`、`&` 等按字面传递；未加引号的 Shell 特殊符号会被拒绝。不执行管道、重定向、变量展开或多条 Shell 命令，复杂逻辑应写入脚本。
- 命令最多 16,384 个字符、128 个参数。

第一项为 `.py` 文件时，Anas 检查脚本后探测系统 Python 3：Windows 依次检测 `python`、`py -3`、`python3`，macOS/Linux 检测 `python3`、`python`。每项最多 2.5 秒，使用工具的实际环境和工作目录运行基础代码并读取版本与实际路径；未安装的 Microsoft Store 链接不算可用解释器，探测不触发自动安装。系统解释器均不可用时，再探测程序包中的备用解释器。选定后直接启动实际绝对路径，普通和交互式工具一致，不修改 PATH；业务脚本失败或缺包不换解释器重跑，取消也不进入保底。系统与内置均不可用时明确报错。

“设置 > 环境”的“内置 Python”默认开启。从下一次请求起，启用“运行环境”的项目和子 Agent 按这个全局设置决定是否向模型提供包内解释器的版本、绝对路径、可用状态、随包依赖和调用格式，由模型选择是否通过 Shell 调用；系统环境检测文字保持原样。需要特定解释器时明确配置命令：`python ...`、`py -3 ...` 和虚拟环境路径不自动替换；Windows 交互式工具的显式解释器应使用绝对路径。

运行时直接使用程序包 `resources/python/`，不向数据目录释放副本；开发环境用 `npm run prepare:python` 准备 `build/python-runtime/<平台-架构>/python/`。构建时移除 pip、ensurepip、setuptools 和 wheel，写入 `EXTERNALLY-MANAGED`；依赖由构建过程管理。自动保底及上下文建议调用使用 `-E -s -B -X utf8`，忽略 Python 环境覆盖、禁用用户 site-packages 和字节码写入，保留脚本同目录导入及业务环境变量。系统解释器参数不变。额外依赖使用独立用户 Python 环境；脚本输出写入工作目录，不修改包内运行时。旧 `runtimes/` 原样保留且不再读取，损坏通过重新安装应用修复。这里是资源归属约定，不是操作系统强制只读或脚本沙箱。维护说明见[用户指南](../data/help/USER_GUIDE.zh-CN.md#运行环境与环境变量)。

上例对应 `scripts/submit.py`：

```python
import argparse
import json
import sys

parser = argparse.ArgumentParser()
parser.add_argument("--mode", required=True)
parser.add_argument("--data", required=True)
parser.add_argument("--verbose", action="store_true")
options = parser.parse_args()
data = json.loads(options.data)
title = data["title"].strip()
if not title:
    parser.error("title 不能只包含空白")
if options.verbose:
    print(f"Mode: {options.mode}", file=sys.stderr)
print(f"已接收标题：{title}")
```

## 结果与交互

工具可以在 `input_schema.properties` 中声明可选字符串 `summary`，请模型用用户的语言简述本次操作。将它留在 `required` 之外，模型即可省略。模型填写时，脚本会在 `{{args}}` 中收到该值，聊天界面也会在工具名旁优先显示它。省略时沿用通用的参数摘要。

成功时 stdout 原样返回模型，可为文本或 JSON；Anas 不解析其中的业务字段来判断成功。需要表示执行失败时应使用非零退出码，诊断日志写入 stderr。错误结果包含原因及已收集的 stdout、stderr；内联 stdout 最多 524,288 字符，stderr 最多 120,000 字符。stdout 超限时附截断说明，成功执行不会仅因截断变为失败。已返回后台句柄的调用可继续读取受管输出；错误或截断不代表没有副作用，不应据此直接重试。

开启“交互式终端（PTY）”时在启动时分配 80 × 24 终端，运行中不能补接。它需要有效能力配置开启“后台工具”，无需同时开启“执行命令”；后台工具关闭时不会向模型提供此工具，但保留选择。

等待与执行合计超过 10 秒后返回后台调用编号：`read_call` 获取 `terminal_id`，`read_call_output` 读取提示，`write_call` 发送文本、按键、EOF 或调整尺寸，`wait_call` 等待完成，`cancel_call` 终止进程树。超时包含等待输入，取消不回滚已经发生的修改。后续输入按[安全模型](SECURITY_MODEL.md)中的终端输入授权与恢复规则处理。

PTY 合并 stdout/stderr，可能改变换行并包含终端控制符；需要保真文件内容的工具应保持非交互模式。执行实现见 [customToolRuntime.ts](../src/main/agent/customToolRuntime.ts)。

## 示例、导入与备份

示例直接读取程序包 `data/examples/`（开发时为 `out/examples/`），启动及恢复备份时原地校验，不向用户数据目录复制或覆盖旧示例。选中用户或外加目录分组后，右侧标题栏显示“添加”和“导入工具”，默认打开包内 `data/examples/tools/`，可多选包含 `TOOL.json` 的工具目录，复制到当前所选来源目录；导入后的副本不随示例更新。

自带示例包括 `read_text_raw`、`baidu-search`、`file_sha256` 和 `json_format`，均需导入后使用，可自由编辑导入的副本。以上工具均使用 Python 3 标准库。百度搜索另需联网和 `BAIDU_SEARCH_API_KEY`；各包 README 说明参数与配置。`read_text_raw` 仅接受最多 512 KiB 的 UTF-8 文件，超限报错，保证限制内正文完整返回。

导入将文件链接和目录链接展开为可编辑的普通文件和目录，按展开后的内容计算大小和数量。导入保留包 ID、命令、脚本和资源，按选择顺序追加。与目标来源中已有工具同名、目录同名或 ID 重复时拒绝整批导入；允许从其他来源导入独立副本；每批最多 128 个目录、10000 项、128 MiB、32 层。全部复制校验后才发布，失败清理本批文件并恢复排序，不覆盖现有工具。

每次运行固定工具名称、命令和 Schema。全局来源的工具调用时按 ID 定位当前目录，项目工具使用运行快照中的目录；脚本及依赖按执行时的文件内容运行，不保存脚本副本。写死在命令中的旧绝对路径不会随改名自动改写。

应用备份包含用户 `tools/`、来源配置、排序及能力选择，保留普通执行权限和内部有效链接。包内示例无需备份；用户数据目录中已有旧副本仍按原规则保全。外加目录、项目引用的工具目录及外部链接目标需另行备份；恢复后失效的工具显示错误。

自定义工具复用框架工具循环、受管调用、取消和副作用恢复。它是用户启用的专用能力，不因启动进程增加通用 Shell 审批；不确定结果仍遵循恢复确认。普通自定义工具不强制模型在最终回复前调用，需要“提交成功才结束”的流程应另行定义完成条件。
