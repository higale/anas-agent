# 数据版本与兼容边界

## 5.0 的明确边界

经用户批准，5.0 使用全新的原生执行数据库 **v1**，不提供旧执行库 v0 → v1 转换，不读取或恢复旧对话、记忆、运行记录和旧版整包备份。旧迁移模块、旧执行结构解析器和未使用的 JSON 迁移框架均已移除。

默认数据目录为 `~/.anas`。只说明从旧目录手动复制兼容配置、`.env`、用户 Skills、工具、子 Agent 和插件代码；不复制旧 `db/`。旧目录不自动读取、清理或覆盖。项目及数据库内容从新目录建立，具体步骤见 [5.0 升级数据说明](../data/help/UPGRADE_TO_5.zh-CN.md)。

配置格式保持独立兼容。4.0 历史布局变化见 [4.x 升级说明](../data/help/UPGRADE_TO_4.zh-CN.md)；该说明不表示 5.0 可以恢复旧执行数据。子 Agent 管理配置 v1 不兼容旧 v0 数组，用户须保全旧文件后重新创建或导入包。

## 当前数据版本

| 数据 | 当前版本 |
| --- | --- |
| settings、models、mcp_servers、skills、tools | 顶层 `version: 0` |
| 子 Agent 管理配置 subagents | 顶层 `version: 1` |
| `AGENT.json`、`TOOL.json`、模型模板和语言包 | 顶层 `version: 0` |
| 项目、项目删除日志、输入历史、恢复事务日志 | 顶层 `version: 0` |
| 文件修改 definition.json、record.json、头像裁剪参数 | 顶层 `version: 0` |
| 缓存、HTTP 跟踪元数据、保全清单 | 顶层 `version: 0` |
| 备份清单 | `version: 0`、`storage_layout: "db-conversations"`；内部执行数据库必须为 v1 |
| catalog、会话 SQLite | `PRAGMA user_version = 1` |

执行数据从 v1 建立后续兼容原点；其他应用格式保留各自已支持的版本。`.env`、标准 `SKILL.md`、供应商协议及原始资源文件不增加应用版本字段。应用发布版本与数据版本分别管理。

## 初始化和校验

启动先回滚中断的当前格式恢复事务，再由 `executionStorageValidation` 检查执行存储。检查只打开包含 WAL 的副本，不改写源文件。全新目录不创建数据库，由正常初始化建立；有应用表的旧版本、未知版本、catalog 缺失而会话或 SQLite 配套文件残留时拒绝启动，不以空库覆盖。

备份恢复只接受当前格式。解压后先检查配置、数据库、归属、附件及资源引用，全部通过才切换正式目录；不会转换旧库。失败时保留原数据和原备份。当前格式的替换、回滚与进程中断恢复使用 `dataReplacement.ts` 的统一事务日志。

## 新增配置与默认值

新增可选字段或分组须有默认值。受支持配置缺少这些项时，由当前解析器正常补默认，不要求重置、不升级格式版本、不增加迁移，也不因此重写原文件。保留有效的 `false`、`0`、空列表和已有显式选择；空字符串是否表示默认由字段定义。

默认值、持久化结构、类型、IPC 和界面须一致。未知格式版本或已提供的错误值仍按对应校验规则报告。字段改名、含义或结构发生不兼容变化时，才需要显式版本升级。

## 当前格式手动修复

修复是数据抢救入口，不以版本字段是否正确决定能否尝试。先保全原始数据，在暂存副本中检查当前结构和引用；对原生结构的错误版本字段可修正为 v1，对旧执行结构保留原文件并报告，不提供转换。

每个数据库独立抢救；单库无法修复不阻断其他独立数据。保留无法恢复的原始数据库、WAL、附件及文件修改材料，不以重置冒充修复。配置只修正可确定的错误字段，保留其他设置；未知项目身份不猜测补造。

文件修改归档修复保留内容、哈希证据、操作身份和撤销引用。源材料损坏或关联证据不足时保留原库并报告；不重放工具、不覆盖后续用户修改。修复、保全或事务发布期间源数据发生变化则停止覆盖。

## 后续格式升级

未来确需更改受支持格式时，在独立 `src/main/migrations/` 中增加必要模块，由启动及备份恢复边界显式调用；不预留无使用者框架，也不在业务读取中夹带转换。

升级须保留受支持基线的数据和引用，支持跳版本、安全重试、源文件保全及失败恢复。升级函数不执行工具或重放外部操作。用已发布格式样本验证；移除受支持路径仍须用户明确批准。

`npm run test:e2e -- --current-data-only` 验证当前配置和原生数据的初始化、读写、手动修复、原文保全及重启。旧库拒绝、WAL、部分修复和失败回滚由行为测试覆盖。
