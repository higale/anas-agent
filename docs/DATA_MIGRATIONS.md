# 数据版本与兼容边界

## 5.0 的明确边界

经用户批准，5.0 使用全新的原生执行数据库 **v1**，不提供旧执行库 v0 → v1 转换，不读取或恢复旧对话、记忆、运行记录和旧版整包备份。旧迁移模块、旧执行结构解析器和未使用的 JSON 迁移框架均已移除。

默认数据目录为 `~/.anas`。只说明从旧目录手动复制兼容配置、`.env`、用户 Skills、工具、子 Agent 和插件代码；不复制旧 `db/`。旧目录不自动读取、清理或覆盖。项目及数据库内容从新目录建立，具体步骤见 [5.0 升级数据说明](../data/help/UPGRADE_TO_5.zh-CN.md)。

配置格式保持独立兼容。4.0 历史布局变化见 [4.x 升级说明](../data/help/UPGRADE_TO_4.zh-CN.md)；该说明不表示 5.0 可以恢复旧执行数据。子 Agent 管理配置 v1 不兼容旧 v0 数组，用户须保全旧文件后重新创建或导入包。

## 项目目录化边界

经用户批准，本次改造不兼容旧 `db/projects.json`／`db/conversations/` 布局，不迁移、不回退读取、不恢复旧布局备份，也不自动清理旧数据。该例外仅限项目与会话布局；配置兼容和新布局自身的保全、修复、备份与中断恢复继续保留。

项目技能和工具来源改为显式目录引用，项目定义仍为 v0。可选 `skill_directories`、`tool_directories` 缺失时默认空列表；读取不改写文件，不自动把源文件夹的 `.agents/skills/`、`.agents/tools/` 转成引用。旧文件及能力选择保留，失效选择可取消；需要继续使用时手动添加总目录并在能力列表中核对勾选。备份保存引用配置，引用的外部文件需单独备份。

## 偏好记忆边界

经用户明确批准，原 catalog 记忆不读取、不迁移、不清理；新建 catalog 不创建旧记忆表或 FTS 表族，已有表保留。全局／项目 Markdown 是新正文，独立 `db/memory.sqlite` v1 保存记忆游标、待检查对话和后台任务。经用户批准，不读取或转换未发布开发版的 v0 记忆库；记忆改造未改变 catalog 与会话版本；当前版本见下表。记忆模型设置是可选字段，缺失按 null 处理，不升级配置版本。

## 活动显示重构边界

经用户明确批准，本次重构使用全新会话库 **v3**，用户自行清空现有对话。应用不迁移、不回退读取会话 v1／v2，也不自动删除旧数据；含旧会话库的备份不能恢复。v3 显示头、组标题与成员归属可在保全后的显式修复中由权威正文重建，不是旧版本转换。catalog、记忆库和配置版本不受此变更影响。

## 当前数据版本

| 数据 | 当前版本 |
| --- | --- |
| settings、models、mcp_servers、skills、tools | 顶层 `version: 0` |
| 子 Agent 管理配置 subagents | 顶层 `version: 1` |
| `AGENT.json`、`TOOL.json`、模型模板和语言包 | 顶层 `version: 0` |
| 项目、项目删除日志、输入历史、恢复事务日志 | 顶层 `version: 0` |
| 文件修改 definition.json、record.json、头像裁剪参数 | 顶层 `version: 0` |
| 缓存、HTTP 跟踪元数据、保全清单 | 顶层 `version: 0` |
| 备份清单 | `version: 0`、`storage_layout: "project-directories"`；内部 catalog 必须为 v2、会话库为 v4（恢复时可升级 v3），独立记忆库存在时须为 v1 |

会话数据从 v3 建立后续兼容原点；其他应用格式保留各自已支持的版本。`.env`、标准 `SKILL.md`、供应商协议及原始资源文件不增加应用版本字段。应用发布版本与数据版本分别管理。

## 初始化和校验

启动先回滚中断的当前格式恢复事务，再由 `executionStorageValidation` 检查 catalog。检查只打开包含 WAL 的副本，不改写源文件。全新目录不创建数据库，由正常初始化建立；有应用表的旧版或未知版 catalog、catalog 缺失而会话或 SQLite 配套文件残留时拒绝启动，不以空库覆盖。

启动在恢复待完成的数据替换与项目删除后、打开运行时前升级受支持的会话库。备份恢复先在解压暂存目录中升级受支持会话库，再检查配置、数据库版本与结构，全部通过才切换正式目录。恢复不逐条校验数据库记录、跨记录引用或附件文件存在性与大小；这些记录的使用仍由运行时处理。失败时保留原数据和原备份。当前格式的替换、回滚与进程中断恢复使用 `dataReplacement.ts` 的统一事务日志。

## 新增配置与默认值

新增可选字段或分组须有默认值。受支持配置缺少这些项时，由当前解析器正常补默认，不要求重置、不升级格式版本、不增加迁移，也不因此重写原文件。保留有效的 `false`、`0`、空列表和已有显式选择；空字符串是否表示默认由字段定义。

默认值、持久化结构、类型、IPC 和界面须一致。未知格式版本或已提供的错误值仍按对应校验规则报告。字段改名、含义或结构发生不兼容变化时，才需要显式版本升级。

## 技能脚本免审移除

经用户批准，技能脚本统一遵循对话权限。`config/skills.json` 中的 `script_auto_approve`、`script_auto_approve_skills` 和项目定义中的 `script_auto_approve_skills` 已停用；读取与备份恢复忽略这些字段，不因其旧值要求修复，也不主动改写原文件。后续正常保存对应配置或项目定义时不再写入这些字段，保留技能目录与快捷、模型选择。技能配置和项目定义仍为 v0，不增加迁移或修改数据库结构。

受支持会话中的历史技能授权记录继续保留和读取，但不再作为自动执行许可；尚未执行的调用需按当前权限重新提交。已有人工批准仍绑定原调用和参数，已完成结果不重放。执行与恢复边界见[安全模型](SECURITY_MODEL.md#57-skill-脚本执行)。

## 当前格式手动修复

修复是数据抢救入口，不以版本字段是否正确决定能否尝试。先保全原始数据，在暂存副本中检查当前结构和引用；对当前结构的错误版本字段可修正为当前版本（catalog v2、会话 v4），对旧执行结构保留原文件并报告，不提供转换。只有版本字段错误与缺少当前结构是不同情况，不能只改版本号兼容旧库。

智能审核调整了 catalog 权限字段约束，catalog 因而升为 v2；该调整不涉及会话库。catalog 按用户要求不提供自动转换。启动和备份恢复拒绝 catalog 版本或权限约束不匹配的数据；手动修复在保全后重建权限字段约束，无效权限值采用默认智能审核，不解释旧权限名称。有效权限值及其他数据保留，修复后验证通过才发布。

重置会话数据库与重置全部项目分开：前者只删除 catalog 及其日志和会话目录，保留各项目 `project.json` 和 `state.json`；后者额外删除项目定义和项目删除事务文件。预览和执行共用实际存在的路径清单；执行前及保全后重新核对，清单变化时拒绝执行。仅重置数据库要求项目定义有效、无待完成的项目删除事务。

每个数据库独立抢救；单库无法修复不阻断其他独立数据。保留无法恢复的原始数据库、WAL、附件及文件修改材料，不以重置冒充修复。配置只修正可确定的错误字段，保留其他设置；未知项目身份不猜测补造。

文件修改归档修复保留内容、哈希证据、操作身份和撤销引用。源材料损坏或关联证据不足时保留原库并报告；不重放工具、不覆盖后续用户修改。修复、保全或事务发布期间源数据发生变化则停止覆盖。

## 后续格式升级

升级实现独立放在 [src/main/migrations/](../src/main/migrations/index.ts)，由启动及备份恢复边界显式调用，业务读写只处理当前结构。新数据库直接创建当前结构，不经过历史升级链。

当前仅支持会话 **v3 → v4**：[独立步骤](../src/main/migrations/conversation-v3-to-v4.ts) 为 `agent_attachments` 和 `agent_queued_attachments` 增加可空 `source_path`，已有 `name` 原样保留，旧来源全部为 NULL。不识别未发布开发版的字段复用方式，不迁移 v1／v2，也不改变 catalog v2、记忆 v1、配置与备份清单版本。

启动升级只处理 catalog 登记且未标记删除的会话，保留未登记目录；先检查所有候选库的版本路径，在临时副本中转换并验证当前结构，不扫描记录内容或执行引用，再将原库及 WAL 等文件保全到系统文档目录 `Anas/backups/before-upgrade/<时间>/`。核对源文件未变后，各库在独立 SQLite 事务中转换并更新版本；失败回滚该库，已成功的库保持完成，重新启动只升级尚未完成的库。保全失败不会开始转换。恢复备份只改解压副本，原 ZIP 不变；完整恢复发布仍使用现有替换事务。

未来按版本顺序注册步骤，连续执行到当前版本，支持跳版本升级。获准淘汰某个旧版本后，删除对应步骤、注册项与专属测试，提升最低支持版本；当前初始化、校验、业务和手动修复不依赖历史模块。未知新版本和已淘汰版本在转换前明确拒绝，保留原数据。

升级须保留受支持基线的数据和引用，支持跳版本、安全重试、源文件保全及失败恢复。升级函数不执行工具或重放外部操作。用已发布格式样本验证；移除受支持路径仍须用户明确批准。

`npm run test:e2e -- --current-data-only` 验证当前配置和原生数据的初始化、读写、手动修复、原文保全及重启。旧库拒绝、WAL、部分修复和失败回滚由行为测试覆盖。

## MCP 工具目录

MCP 配置继续使用 v0。服务条目新增可选 `tool_catalog`（连接配置指纹与工具定义）和 `tool_choices`（工具名到开关）；缺失时分别默认无目录、全部启用。应用启动不连接服务，目录由手动或按需启动成功后更新；工具选择独立保存。无需数据库升级或配置迁移。手动修复先保全原配置，尽量保留有效工具定义和选择；无法识别的目录指纹不猜测，保留连接配置供重新发现。

## 能力选择简化

经用户批准，项目和子 Agent 设置改为整项复选框。旧 MCP 非空工具细选视为选中整个服务，空细选视为关闭；插件任一贡献被选中视为整个插件选中。普通技能旧快捷或模型任一选中视为技能选中，实际用途继续受全局设置限制，项目技能两种用途均启用。最外层分组模式与定制名单保留，切换全部或关闭不清空定制选择。读取不自动写回，正常保存采用整项选择；不新增格式版本或迁移。此规则只处理可编辑定义，已有会话冻结的运行配置及能力交集继续保留具体选择。
