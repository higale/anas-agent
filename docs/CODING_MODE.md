# 编码模式

编码模式是普通工作区项目的独立选项，在“编辑项目”中开启。它增加编码工作规范、项目规则加载和面向任务续接的压缩摘要；不切换模型、不自动启用工具，也不提高访问权限。普通模式拥有相应工具时仍可编写代码。

编码模式不依赖“定制能力”开关。默认项目固定使用默认设置，目前关闭编码模式；简单对话不提供此选项。修改项目设置影响之后启动的任务，已经运行或等待恢复的任务继续使用其运行配置。

## 与普通模式的区别

| 项目 | 普通模式 | 编码模式 |
| --- | --- | --- |
| 主 Agent 指令 | 通用指令和所选上下文 | 额外加入编码工作规范 |
| 项目规则 | 不启用自动规则加载机制 | 按目录加载 AGENTS 规则并加入系统消息 |
| 结构化文件操作 | 按工具及授权规则执行 | 额外检查目标目录规则，必要时先让模型看到新规则 |
| 压缩摘要 | 保存主要话题、决策和继续对话所需的上下文 | 额外保存修改、验证证据、失败尝试和待办事项 |
| 上下文预算 | 使用模型配置的输入容量和压缩阈值 | 为动态项目规则预留输入空间 |
| 默认图标 | 文件夹 | 花括号；自定义图标通常保留 |

编码工作规范要求先检查相关文件、保留用户已有改动、聚焦根因、按项目要求验证，并明确区分解释、审核与实施。审核请求本身不授权修改、提交或推送。规划、子 Agent、编辑和命令相关指令随实际可用能力提供；这些指令不能替代模型、工具和授权配置。

## AGENTS 规则如何进入上下文

应用读取适用规则的全文，在模型调用前通过 `<project_rules>` 区块追加到系统消息。区块包含来源路径、适用目录、快照标识和文件内容。模型不需要先调用文件读取工具；规则内容会发送给所选模型供应商，并占用输入 token。

### 查找范围与优先级

- 每个源文件夹向上查找最近含 `.git` 文件或目录的祖先，以它作为规则查找边界；找不到时以源文件夹自身为边界。
- 沿边界到目标目录的路径加载规则。更深目录的规则只适用于其目录树，优先于祖先规则；兄弟目录的规则不互相适用。
- 同一目录优先使用 `AGENTS.override.md`，仅当它不存在时使用 `AGENTS.md`，不会合并两份文件。存在但为空的 override 也会取代同目录的 AGENTS 文件。
- 首次请求前读取各源文件夹适用的规则链，最初只将主工作目录的规则链加入系统消息。其他源文件夹和更深子目录的规则随结构化文件操作的目标路径激活或发现，不预先遍历整个项目。

例如：

```text
repo/
  .git/
  AGENTS.md
  src/
    AGENTS.md
    ui/
      AGENTS.override.md
      AGENTS.md
```

操作 `src/ui/` 中的文件时，适用根目录 AGENTS、`src/AGENTS.md` 和 `src/ui/AGENTS.override.md`；同目录的 `src/ui/AGENTS.md` 不加载。

### 运行快照与新规则

规则按运行保存快照。一个目录首次检查后，规则内容或“没有规则文件”的结果都会固定；本次运行后续不会重新读取该目录的变化。尚未发现的目录在首次涉及时读取。修改规则后，应启动新一轮任务使已检查目录的新规则生效，恢复原运行仍使用原快照。

结构化文件操作会根据解析后的目标路径发现规则。如果待执行写操作依赖尚未出现在本次模型请求中的规则，写入会先返回 `NOT EXECUTED`，新规则加入下一次系统上下文，由模型重新决定操作；应用不会自动重放原写入。规则总量超出请求预算时，也可能要求缩小操作批次。

任意 Shell 命令不会自动解析所有受影响路径；未声明结构化文件目标的 MCP、自定义工具也没有这一目标检查。编码指令要求模型进入新目录前先用结构化文件工具检查，并读取命令可能影响的其他路径规则。不能将规则加载机制理解为对所有命令目标的自动覆盖。

规则读取沿用访问授权边界；严格审批模式下读取项目源文件夹外的规则可能需要批准。它不依赖模型主动调用“文件读”工具，也不会因关闭该工具而自动停止。授权细节见[安全与审批模型](SECURITY_MODEL.md)。

## 压缩与上下文预算

未设置项目自定义压缩提示词时，编码模式使用专门的压缩补充指令，保留当前目标和授权范围、项目约束、确实发生的文件修改、验证命令及结果、失败尝试、未解决问题、后续步骤和关键引用。未执行的测试不能写成通过，计划不能写成已完成。

摘要不替代单独加载的项目规则，也不复制完整源码、补丁和日志。自动压缩仍受模型的压缩开关和阈值控制。

设输入容量为“最大上下文减去最大输出”，规则机制额外预留输入容量的 5%（向上取整），至少 256 token。自动压缩阈值取用户配置阈值与预留后的输入预算中的较小值；这不改变模型配置中的最大上下文或最大输出。

规则读取、编码格式或容量检查失败时会明确报错，不以静默截断规则继续执行。当前规则文件要求 UTF-8、普通文件，单文件上限 64 KiB，单次运行累计规则内容上限 512 KiB；目录发现也有数量与深度限制。规则和任务必需上下文无法容纳时，应缩小范围、精简规则或选择更大上下文的模型后重新开始任务。

## 项目自定义压缩提示词

普通工作区项目的提示词区域提供“项目提示词”和“压缩提示词”两个标签。两项提示词仅在开启“定制能力”时允许编辑并生效；关闭后隐藏编辑区、使用默认行为，保留已有自定义内容以便重新开启；默认项目保持只读预览，简单对话不提供项目级定制。

压缩提示词编辑框留空表示使用当前普通／编码模式的内置默认，不自动填入默认全文。“载入默认”将当前模式和语言对应的默认内容放入草稿，便于修改。非空自定义文本完整替换内置模板；清空即可恢复默认。切换编码模式不覆盖已有自定义文本。所有修改随外层项目“保存／取消”统一处理。

自定义全文必须且仅包含一个 `{conversation}`，用于插入待压缩历史；`{output_language}` 可选，用于插入配置的默认语言。最长 50,000 字符，保存前校验占位符。自动与手动压缩使用同一模板，并按该模板计算摘要输入预算。

配置使用可选的 `compression_prompt` 字段，缺失、空字符串或纯空白均使用默认；清空后保存移除字段。仍使用原有 v0 格式，不增加迁移。自定义全文随主任务的运行配置保存，运行中或恢复时不因项目设置后来改变而替换；新任务使用最新项目设置。子 Agent 继续使用其编码模式对应的内置模板，不继承项目自定义全文。

## 子 Agent 与预览

子 Agent 继承父任务的编码模式，用于规则加载和压缩策略。主 Agent 的编码工作指令不会重复加入子 Agent 的专用提示词；子 Agent 仍使用自身配置的指令及有效能力。

项目编辑窗口左侧标题区菜单始终提供“完整提示词”“压缩提示词”和“预览请求”。压缩提示词菜单只读展示当前项目草稿将使用的完整模板：开启定制能力且自定义非空时显示自定义内容，否则显示当前模式的内置默认；编辑仍在同名标签中进行。可检查当前项目草稿生成的提示词和请求。预览不会提前发现未来文件操作可能涉及的全部子目录规则，也不是正在运行任务的历史快照。
