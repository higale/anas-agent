# Anas 主线交接

更新时间：2026-11-21。本文记录当前实现与验证边界；逐次开发和历史验收记录保留在 Git 历史。

## 主线与发布基点

- 原生实现来自 Anas Next `553fded16ee7ac1205e9283a37f3fa80e932da12`，保留 Anas 的 UI、设置和插件操作。Next 保留重构历史，后续开发以本仓库为准。
- 旧框架快照 `codex/legacy-framework-4.0.9` 固定在 `460f58de4f3d914456e3ca64b6e628e845769ecb`，长期保留。
- 本次同步版本为 `5.2.20`。已确认发布源码由 `refs/anas/github/v<版本>` 记录；发布成功并核对源码后更新对应基点。开发差异由 Git 自动生成，日常开发不修改正式版本号。
- 源码同步和安装包分别以 [GitHub 源码](https://github.com/higale/anas-agent)与 [Release](https://github.com/higale/anas-agent/releases)为准。独立源码快照、版本递增及发布基点更新遵循[发布流程](SOURCE_PUBLISHING.md)。
- 普通需求在 `main` 开发；复杂需求使用临时 `codex/` 分支，验证后合回并删除，旧框架快照分支除外。

## 当前执行与数据

- 普通聊天、简单聊天、审核、压缩、子任务、历史编辑和恢复共用原生协调器、`NativeRunHost` 与一份执行状态。LangChain、LangGraph、Deep Agents 及旧执行器、图存储、middleware 和适配依赖已移除。支持 OpenAI Chat Completions、Responses 和 Anthropic 协议。
- 默认数据目录为 `~/.anas`，开发与打包一致，保留 `--data-dir`。不自动发现、导入或清理 `.galeAnas`、`.anas-next`。测试使用隔离目录。
- 当前 catalog 为 **v2**，会话库为 **v4**，独立记忆库为 **v1**。项目定义为 v0，子 Agent 管理配置为 v1；完整版本表与历史不兼容边界见[数据兼容规则](DATA_MIGRATIONS.md)。从旧框架升级只复制兼容配置与扩展资源，不复制旧 `db/`；步骤见 [5.x 升级说明](../data/help/UPGRADE_TO_5.zh-CN.md)及[英文版](../data/help/UPGRADE_TO_5.en.md)。
- 项目定义保存于 `db/projects/<项目ID>/project.json`，跨项目界面状态保存于 `db/projects/state.json`，对话资源位于各项目的 `conversations/` 中，创建后归属固定。旧 `db/projects.json`／`db/conversations/` 不读取、不迁移、不自动清理，也不恢复其备份。
- 启动在副本上检查 catalog 版本、必需字段和权限约束；打开会话时核对其格式与身份。无关目录条目不阻塞启动，缺失的可选界面状态使用默认值。当前格式自身的备份、修复和事务恢复继续保留。
- 手动修复先保全原件，逐项抢救项目与会话，再重建索引；无法恢复的内容隔离保留并报告，补齐必要结构，以程序可进入为目标。切换前实际打开存储验证，不转换旧布局或重放外部操作。
- 模型完整响应与工具结果先持久化，观察事件不作为执行证据。工具活动、审批与追加指令关联应用调用 ID；取消先持久化，再等待资源释放。历史编辑等待受影响任务退出后原子替换，恢复不重放已完成工具。

实现合同见[原生执行设计](NATIVE_EXECUTION.md)，文件职责与恢复行为见[存储设计](CURRENT_STATE_STORAGE.md)。

Shell 已移除 `keep_processes`，仅管理直接 Shell；已派发且已交接调用可跨轮继续，显式取消／应用退出停止 Shell，不递归关闭子进程。“工作区菜单 → 进程列表”位于项目记忆下方，在右侧显示当前对话及子 Agent 的 Shell 和已知直接子进程，支持刷新和按身份手动终止。Shell 的模型返回保留原始标准输出，仅按需附带状态或进程 PID／名称；`read_call`／`wait_call` 重新核验进程身份，不直接复用旧的存活结论。观察是尽力而为，终端挂断仍可能影响连接终端的程序；详见[安全模型](SECURITY_MODEL.md#76-受管工具执行与输出)。Windows 已验证真实进程退出、保留独立子进程和列表操作；本轮未执行 macOS 桌面交互回归。

发布复审已修正 Shell 工具对原始标准输出的说明；Python 通知统一通过共享详情格式保留底层诊断。历史编辑测试同时校验已提交输入的即时显示和尚未接受输入时的权威历史，避免将两者混为一谈。

PTY 回归通过内部结果检查退出状态，通过明确输出标记获取独立子进程 PID，不假定模型返回始终为 JSON，也不依赖终端控制序列之外的换行布局。

Windows 普通与 PTY Shell 在共同执行入口按 Node `child_process` 的规则对环境变量做大小写去重，避免继承的 `Path` 遮蔽带内置命令目录的 `PATH`，显式空值仍保留。

## 当前显示、能力与记忆

- 活动组标题和成员归属与正文同事务增量维护。展开轮次只读取外层行和组标题，展开组后读取该组轻量成员，正文再按需读取；各范围独立返回差量，共用单一虚拟时间线。运行计时与折叠不改写执行状态，详见[活动显示架构](ACTIVITY_WINDOWS.md)。
- 项目已取消“定制能力”总开关，直接使用保存的能力、提示词和限制，新项目默认能力全开，不转换既有配置。MCP／插件总分组使用“全部／定制／关闭”，切换保留内部选择。
- 项目技能支持自定义总目录，技能“快捷、模型”复用能力选择，项目“免审”独立保存于可选 `script_auto_approve_skills`，默认空列表；全局免审继续独立生效。主 Agent 不加载子 Agent 私有资源，子 Agent 只附加所属包资源。详见[技能指南](../data/help/AGENT_SKILLS.zh-CN.md)和[安全模型](SECURITY_MODEL.md)。
- 偏好记忆正文为全局／项目 Markdown；前台主动记忆与后台提取共用对话游标。只有“设置 → 记忆”明确选定模型后才运行后台整理，不回退到会话模型。旧 catalog 记忆不读取、不迁移、不清理，新建 catalog 不创建旧记忆表。详见[后台偏好记忆](CURRENT_STATE_STORAGE.md#后台偏好记忆)。

## 5.2.20 同步范围

移除 Shell 的 `keep_processes` 参数，以直接 Shell 的退出作为调用完成边界，取消和退出应用不递归终止子进程。新增对话进程列表，观察和手动终止均核验进程身份，只列直接子进程。精简模型返回，保留无需额外状态时的标准输出原文；后台查询重新核验存活状态。

菜单与侧栏共用内置面板图标映射，区分进程列表、项目记忆和记忆活动。双语指南、执行与安全文档同步当前边界。配置与数据库格式不变；当前 Shell 定义不再接受旧 `keep_processes` 参数，已完成调用记录不重新执行。

发布审计更新 MCP SDK、shell-quote、Zod 及存在上游安全告警的传递依赖；本机移除已不在锁文件内的旧框架残留。发布工作流在 Windows 和两种 macOS 架构上增加真实 Shell／PTY 生命周期及进程观察测试。

修正 Responses 兼容服务在工具调用后附加空 assistant 占位消息的回放：请求省略调用末尾的空占位，保留原始记录、有效正文、拒绝信息与推理项关联，避免供应商转为 Chat 格式时将调用与结果隔开。

## 验证边界

本轮 Windows 隔离环境完成整仓行为测试、1002 项 DOM 测试、类型检查、lint、依赖完整性及构建。整仓测试与构建并发时有三项超时，所属两份测试文件已串行复测通过。生产依赖通过官方 npm registry 审计，未报告已知漏洞。

实际 Electron 回归通过进程列表观察与手动终止、普通／PTY 生命周期、关闭窗口及退出应用清理、启动响应性、Python 准备失败与设置重置；项目记忆和记忆活动图标已通过隔离界面检查。30 份文档的 240 个本地链接及锚点检查通过。

Responses 空消息问题已用真实失败 HTTP 记录定位：仅省略空占位后，同一供应商请求返回 200 并完成响应，未重新执行 Shell。修复新增流式、非流式、存储回读与语义保留测试，相关协议及原生请求集成共 267 项通过。此项验证不代表其他模型或供应商验收。

本轮未执行 macOS 桌面交互回归或本地安装包复测，公开安装包验收以三平台发布工作流为准。历史 Windows、Next 整仓和包内验收不代表当前提交复测；本机受控服务不能作为真实供应商验收。后续修改按 [AGENTS.md](../AGENTS.md) 与[贡献指南](../CONTRIBUTING.md)执行相应检查。
