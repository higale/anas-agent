# 当前状态存储

会话状态由应用的原生执行内核与 v1 SQLite 存储持有。模型、工具、审批、摘要、调度及恢复共用这一份权威状态。具体执行边界见[原生执行设计](NATIVE_EXECUTION.md)，验收进度见[运行时替换交接](HANDOFF.md)。

长期记忆由应用的 `SqliteMemoryStore` 独立管理，不依赖执行框架接口。记忆工具和召回直接调用业务接口；现有记录、命名空间与全文索引表不变，正文及索引在同一事务中更新。保留的非记忆记录不会在清理记忆时删除。

历史工具调用缺少结果时，请求投影明确告知模型结果未知，不据此执行、重试或宣称取消。补充结果只存在于模型请求，不写入持久消息；无法配对的原始工具结果保留在完整历史，但不作为协议工具消息发送。结果按对应 AI 消息的调用批次配对，后续批次复用相同 ID 不能回答早先调用。摘要边界始终定位完整历史，不能使用请求投影后的数组下标。

每个 Agent 保存一份当前执行状态和完整有序历史，不保存可回放的状态版本链。完整模型响应与逐项工具结果提交 SQLite；未完成流只保存在运行内存及临时展示中，崩溃后不把未提交进度视为完成结果。

当前 catalog 为 v2，会话库为 v1；5.0 经用户批准使用全新数据库，不迁移旧 v0 执行库，不恢复旧对话、记忆、运行记录或旧版整包备份。启动检查 catalog 版本、必需字段和权限约束，不匹配时在运行前报错。智能审核造成的 catalog 约束变化不自动转换，通过手动修复保全后处理；当前格式的备份、修复和崩溃恢复保留，配置版本独立保持。具体范围见[数据兼容规则](DATA_MIGRATIONS.md)。

4.0 是经用户批准的会话存储兼容边界：旧 `sqlite/` 中的对话目录与全部记忆，以及根目录的 `projects.json`、`input_history.json` 弃用，不迁移、不回退读取、不自动删除旧文件；旧备份不能导入。除下述子 Agent 目录化例外，其他全局配置仍使用原 v0。

项目、输入历史、插件数据和头像的手动恢复步骤见[4.x 升级数据说明](../data/help/UPGRADE_TO_4.zh-CN.md)。项目定义和输入历史仍使用现有 v0 格式；头像资源使用 `config/assets/`，旧根目录 `assets/` 不读取、迁移或纳入新备份，未恢复时初始化默认头像。手动恢复这些文件不恢复旧对话或记忆。

## 文件与职责

数据清理白名单与备份默认目录见[数据清理](DATA_CLEANUP.md)。旧布局文件只在用户选择“未知文件”后按预览删除，不在启动时清理。

```text
<dataDir>/
  config/
    *.json
    assets/                       # 头像原图、裁剪参数及生成图标
  subagents/_system/<内置包>/      # 应用维护、随版本更新，只读
  subagents/<用户包>/
    AGENT.json                    # 稳定 ID、名称、描述、模型选择与能力
    PROMPT.md                     # 系统提示词
    skills/<技能>/SKILL.md         # 可选，仅所属 Agent 使用
    tools/<工具>/TOOL.json         # 可选，可携带脚本和资源
  db/
    catalog.sqlite
    project-write.json             # 仅项目定义／界面状态发布事务期间存在
    input_history.json
    plugins/<插件ID>/             # 插件独立数据、通用设置及安装状态
    project-deletion.json          # 仅项目删除事务期间存在
    project-deletion.stage.json
    projects/
      state.json                  # 排序、置顶、折叠与对话显示顺序
      <项目ID>/
        project.json              # 项目定义与设置
        conversations/<主对话ID>/
          conversation.sqlite
          attachments/<threadId>/<attachmentId>/content.<ext>
          file_edits/<runId>/<operationId>/...
          tool_results/<内容哈希>.txt
  tmp/conversations/<主对话ID>/
    message_edit/
    direction/
```

`db/projects/<项目ID>/project.json` 保存项目定义与设置，`db/projects/state.json` 只保存按项目 ID 引用的界面状态，`db/input_history.json` 保存全局输入历史和置顶输入，`db/plugins/<id>/` 保存所有插件的独立数据、通用设置和安装状态；`anas-installation.json` 记录启用状态和标题栏图标设置。用户插件代码直接位于 `plugins/<id>/`，内置插件位于 `plugins/_system/<id>/`，均无额外的 `package/` 层级。项目重置只删除项目元数据、catalog 及对话资源，保留输入历史和插件数据。项目修复保留同目录其他文件，并在切换前核对源数据未变化。

子 Agent 定义只从目录包读取。`web-researcher` 和 `project-analyst` 放在 `examples/subagents/`，不自动加载，导入后作为普通用户包使用。仅 `general-purpose` 内置于 `subagents/_system/`，启动时镜像随包内容，不改动用户包；内置定义和全部文件只读，不可删除或改名，能力全开，固定使用父 Agent 的模型，仅允许切换整个 Agent 的启用状态。`config/subagents.json` v1 保存 `order`、`external_directories`（稳定 ID、显示名及绝对路径；缺失默认空列表）和整个 Agent 的 `disabled`，不再保存内置覆盖配置。包内文件不保存宿主启停状态。自定义提示词统一从文件树的 `PROMPT.md` 编辑；内置文件只可预览，定义和文件保存入口均拒绝写入。

包内资源选择属于能力配置：`capabilities.skills.package` 和 `capabilities.custom_tools.package` 按包内 ID 保存布尔开关，未指定时默认启用；整体分组关闭仍优先。自定义 Agent 写入自己的 `AGENT.json`；内置包不提供资源开关。包内 ID 不包含 Agent ID，复制包后选择仍有效。运行时先解析为明确资源列表，再应用父级限制与同名规则。

包 ID 不随名称和排序改变，私有资源使用 `subagent:<ID>:skill:<名称>` 和 `subagent:<ID>:tool:<工具ID>`，不进入全局目录。项目的包内资源选择仅用于子 Agent 能力上限，不向主 Agent 暴露资源。包内同名资源优先，先应用父级限制，再处理同名覆盖。

外部目录直接引用其下的包，内置和用户包优先于外部来源；重复 ID／名称和无效包在来源中报告，缺失目录不阻塞其他包。移除来源只解除引用；不可用包的宿主开关和顺序保留。

定义编辑和删除使用 `subagents/.transaction/` 保存事务记录，配置文件作为提交标记；外部包的暂存与旧目录保留在同一外部卷的 `.anas-subagent-<事务ID>/`，恢复后清理。再次读取前完成恢复，活动工具目录不能替换或删除。本地整包随备份保存，外部包只保存引用、文件需另行备份；未知文件清理保留整个 `subagents/`。此次改造经用户批准，不迁移或读取原 v0 数组配置；原文件保留并报错，需保全后重新创建或导入包。

对话持久资源统一位于 `db/projects/<项目ID>/conversations/`，临时草稿仍在 `tmp/conversations/`。开发期间的根目录 `conversations/` 不读取、不迁移、不纳入备份，也不自动删除。

侧栏默认项目仍是项目数组中的固定 ID 成员，展示时独立置底。项目的可选 `sort_order` 和 `thread_order` 保存手动显示顺序；缺失时沿用自动排序，无需迁移。拖动只调整同组、同置顶状态的条目，不更改项目归属或对话时间。手动排序后的对话按保存顺序显示，新对话置于未置顶条目前，运行状态和消息更新不改变顺序。

旧 `plugins_data/` 不自动读取、迁移或删除；完全退出程序并备份后，可将它整体移动为 `db/plugins/` 恢复，内部格式不变。目标已有数据时先单独备份，目录替换不合并数据。插件代码仍在 `plugins/`，临时文件仍在 `tmp/`。

[AgentStorage](../src/main/agent/agentStorage.ts) 的 catalog 保存主对话列表、项目归属、库定位、工作区选择及共享记忆。列表查询不打开全部会话库；catalog 的运行状态只是列表投影，会话库保留权威产品状态。

一个主对话及其全部子 Agent 共用物理目录和会话库，各自使用独立的应用 thread ID。目录名使用既有主对话 ID，不新增另一套 session ID。父子关系、运行、审批、效果记录和结果交付可在同库事务内更新。创建时固定项目归属，之后不可更换项目；catalog 的归属决定会话路径，打开时核对库内身份和项目。

[ConversationRuntimeDirectory](../src/main/agent/conversationRuntimeDirectory.ts) 按需创建 runtime，保护运行、审批等待及在途操作持有的连接，按最近使用顺序淘汰空闲连接，最多保留 32 个空闲会话。空闲连接和整份消息状态的内存缓存有独立生命周期。

日常打开会话检查当前格式、执行归属、待处理输入／审批及清理记录；恢复只核对并协调当前运行，不逐条扫描全部历史正文。首屏读取最近的消息窗口，待办、审批和修订标识直接读取执行元数据。正文在实际读取时校验内容身份和格式；备份、手动修复及显式完整验证继续检查全部历史、索引、效果记录和 SQLite 完整性，未显示的历史损坏不因打开另一页而提前阻塞界面。

重试按钮根据运行与消息索引定位失败边界，只读取该失败的输入和最后一批消息；缺少可选失败标记的历史 v1 记录仍按完整协议检查判断资格，实际重试提交继续完整核对历史。上下文用量预览跳过已被摘要覆盖的正文，剩余消息分批读取并让出事件循环；摘要后没有用户消息时，按可见消息索引倒序补读最近用户输入用于记忆召回，该输入不重复计入模型历史。读取期间修订变化时丢弃结果重算，不发布混合版本的状态。

项目定义和界面状态通过 `db/project-write.json` 发布事务保存，中断后完成已记录的发布；项目删除另使用删除日志协调 catalog 清理。项目改名不改 ID 或目录。缺失界面状态按默认值读取，损坏定义明确报错。

本次项目目录化不迁移、回退读取或恢复旧布局备份。旧 `db/projects.json` 和 `db/conversations/` 不参与启动、读写或项目重置，其存在不影响新布局，原始文件保留；新备份使用 `storage_layout: "project-directories"`，不包含这些旧文件。记忆仍存于 catalog，工具和召回行为不变。

## 运行中的模型选择

对话产品记录只保存模型 ID 和参数预设 ID；模型、供应商和预设参数以当前应用配置为准。[模型选择解析器](../src/main/agent/modelSelection.ts) 在每次模型请求前重新读取选择和参数。主对话必须有明确选择；子 Agent 未指定模型时沿父子关系实时继承，指定模型后独立解析自己的选择，不复制父 Agent 的参数。

输入框在运行及等待审批期间仍允许选择模型和预设。运行完成事件在资源清理后读取最新对话元数据，保留清理期间修改的模型和预设。设置保存后广播配置，界面立即重算上下文容量、输出预留和压缩阈值；更换请求配置后不沿用旧请求的服务端 token 用量。已发出的请求使用原参数，后续请求及其准备阶段使用新参数。请求准备期间再次修改配置会重新准备，持续变更超过重试上限则明确终止。自动与手动压缩在准备和重试时也检查最新配置；合法变更重新准备摘要输入与预算，失效配置明确终止。模型能力校验和附件、token 投影读取同一持久化摘要边界，已压缩历史不再要求新模型具备原历史的工具或图片能力。

模型、供应商或预设被删除、配置无效、有效上下文要求新模型不支持的工具或图片、压缩后仍超出窗口，以及供应商明确拒绝请求时，当前运行以失败结束并展示原因。不会自动切换其他模型或回退旧参数。额外模型参数不得设置由运行时管理的 `input`、`messages`、`system`、`conversation`、`previous_response_id`、远端 `prompt` 模板或旧式 `functions`／`function_call` 工具字段，避免覆盖或绕过 持久上下文与工具定义。原生当前状态及已完成工具结果保留，修正选择后可以在同一对话继续。

模型请求失败后，错误下提供“重试”和“重试（不返回工具结果）”。两者在同一运行中回到模型请求，不新增用户消息、不重放已完成工具；后者在同一事务中将最后一批工具返回值替换为用户主动不返回的说明，更新会话正文、历史索引和活动引用；对话展示及后续模型请求直接读取替换后的持久内容，保留调用 ID 和工具已执行的事实。效果日志所需的原始证据保留，其余失去引用的旧正文按既有规则回收。只有错误前紧接完整工具结果且其后没有用户输入时才显示并允许“不返回工具结果”；输入“继续”后发生的错误仅提供普通重试。当前 v1 执行上下文增加可选的 `model_request_failed`、`model_failure_boundaries`，工具消息上下文增加可选的 `result_withheld` 标记；缺少失败标记的现有记录仅在已保存的响应指针为空、确认处于下一次模型请求边界时允许重试。替换后的工具返回值随备份、重启和后续对话保留。中间错误同样提供按钮：用户确认后移除后续对话和运行，从选中的错误位置继续；已执行的工具操作不会撤销。历史失败按完整消息边界和已保存的失败类型判断，手动删除后续内容后仍可重试保留的错误。重试绑定目标运行及当前历史修订，活跃、清理中、已过期的请求不能重试；原始执行成功不会被改写成失败。

模型输出恢复与网络重试共用同一失败点最多两次自动恢复的预算。会话内自动、手动压缩的请求失败也由同一协调器计数与等待，压缩内部不再叠加重试；独立调用压缩服务仍保留最多两次重试。可选的 `model_recovery` 保存次数、原因、等待截止时间、请求在途标记和纠错反馈类型；现有 v1 缺少该字段时正常读取。开始请求前持久标记，重启不会免费重发已占用的恢复次数；完整有效响应提交后清零，用户手动重试重新计数。默认两次等待为 0.5 秒、1 秒，供应商提供有效 `Retry-After` 时采用不短于该值的等待，支持取消。非法工具调用与截断的工具调用整次响应不执行；纯文本达到输出上限时保留已生成内容并继续，恢复耗尽仍标为失败且保留手动重试。纠错说明仅在最终请求中作为应用通知附加，既不伪造用户历史，也不改变记忆召回查询与历史压缩边界；上下文预览计入通知。附件读取、提取失败及不可用附件向模型提供明确说明，原文件保留；不增加本地图片兼容性拦截或自动转换。

自动恢复的安排、开始、有效响应、次数耗尽，以及手动重试的请求、启动、拒绝和运行结束，写入现有普通运行日志（`agent-model` 来源）。记录会话、运行、修订、模型活动、原因、次数、等待时间、原始错误链及可用的供应商请求 ID；异常输出保留有长度上限的诊断片段。日志沿用设置中的级别和保留期限，不新增独立文件或数据库，不将诊断内容送回模型，记录失败不改变执行结果。

上下文显示、压缩预算和发送前容量校验共用按当前协议实际发送内容计算的 token 估算，包含重放的推理、工具结果、Responses `instructions` 及输出 JSON Schema，不把旧请求的输出用量当作新输入。请求级参数只计一次，消息片段计数不重复计入。实际保留的每张图片按 1024 token 计入，覆盖附件、工具结果及 Responses 原生生图、代码执行结果，不按图片 URL 或 Base64 长度计数；已省略或被摘要覆盖的图片只计保留文字。Chat Completions 包含适配层追加说明及重复携带的工具文字。服务端用量只校准模型配置及实际输入投影匹配的历史前缀，再加上该响应与后续消息；代码审查的合成报告不遮蔽真实模型用量，报告及工具结果仍计入后续消息。附件移除或截断、摘要替换、记忆召回和工具定义变化都会使旧校准失效，输入未变时保留有效校准。发送前容量校验也保留有效服务端校准的下限，缩小窗口或关闭压缩不会绕过该校验。

记忆召回先于压缩预算判断。自动和手动压缩都检查完整摘要输入的容量，不能通过丢弃摘要源来推进历史截断；输入超限或摘要为空时明确终止并保留历史。压缩保留完整的待处理图片及工具调用关系；本地或供应商容量溢出进入应用压缩和工具结果收缩，必要上下文仍无法容纳时明确终止。压缩统计使用压缩前的有效上下文及最终发送投影，包含系统指令和工具定义。转入简单聊天的历史先按原始完整历史 应用摘要边界，再剔除工具执行消息及客户端调用，保留有效摘要及其后消息；被移除调用所依赖的 Responses 推理 ID 一并去除，推理内容和加密内容保留，未受影响的原生输出继续原样重放。预览、能力校验和发送遵循同一顺序。失败或取消后，token 展示从实际保留的完整历史 恢复，无法重算时清空旧展示。

模型协议或参数变更后，以及空闲或待审批对话切换工具权限后，界面通过只读上下文接口重新投影当前历史，完成前隐藏旧估算、显示加载态并禁用手动压缩；模型窗口及压缩阈值立即更新，已展开的面板保持打开。只读投影复用 Agent 的指令、工具与附件组装，工具定义不依赖执行服务实例，不调用模型或创建运行、不写执行状态、不启动 MCP 连接。运行中的预览使用当前实例已组装的产品配置；等待审批时按恢复请求会使用的当前提示词和已保存的运行能力配置重新投影。任务结束、重新打开或修改影响上下文的项目／应用配置时，按下一轮的当前配置重新预览，忽略已过时的异步结果。恢复运行不沿用旧实例的用量事件，持久化快照通过只读接口核对后再展示。子 Agent 仍保留自己的角色及父级能力约束。

## 表与正文引用

[NativeConversationDatabase](../src/main/agent/nativeConversationDatabase.ts) 使用单一 SQLite 连接；[NativeExecutionStore](../src/main/agent/nativeExecutionStore.ts) 保存执行状态和精确正文。

| 表 | 内容 |
| --- | --- |
| `execution_state` | 每个 thread 的唯一执行头、运行归属、修订、阶段、上下文和审批 |
| `execution_message_bodies` | 按内容身份保存完整应用消息、供应商原始内容及工具结果 |
| `execution_messages` | 当前完整历史的有序正文引用 |
| `execution_model_calls` | 模型消息与其调用批次的有序身份 |
| `execution_calls` | 当前批次的准备状态、调用及已保存结果引用 |
| `execution_effects` | 已准备调用、外部效果意图、确认／重试计数及结果引用 |

产品运行、活动、子任务、摘要、队列、受管结果和资源清理表保留各自职责。活动索引引用权威消息正文，不复制一份可用于执行的消息状态；显示投影和分页不能决定工具是否执行。历史摘要保存完整消息边界，压缩不删除原始历史。

## 提交与生命周期

[NativeRunOwner](../src/main/agent/nativeRunOwner.ts) 将执行提交、产品状态和正文引用放入同一事务。先保存输入或外部效果意图，后执行；已保存工具结果在恢复时直接消费。事务失败整体回滚，未确认效果必须走明确恢复策略，不盲目重试或伪造成功。

[NativeRunHost](../src/main/agent/nativeRunHost.ts) 统一持有执行与清理归属。取消先持久化再通知信号；完成、失败或取消记录不等于资源已经释放。后台执行、子任务、归档及文件清理真正排空后才释放会话；超时保留归属和可重试 outbox。审批暂停保留同一运行身份及完整结果，恢复核对审批代次，不依赖旧框架流或转发器。

正文及引用从当前历史、活动、待处理调用和效果中计算保留范围。历史编辑通过专门事务替换受影响引用；活动分页只读取所选区间。已保存状态与预览副本分离，不把界面对象的修改写回执行状态。

## 消息展示与维护

图片附件发送限制为每张 25 MiB；本地图片预览不设文件字节上限。消息缩略图按需生成，点击后由 Electron 的 `anas-image` 本地协议加载原文件，原图不再经 IPC 转为 Base64。发送后的附件仍从归档原文件预览。

Responses 流式生图结果通过 SDK 的响应转换生成标准图片块供界面展示，同时保留原生输出用于后续请求重放；展示图片不会在历史请求或 token 预算中重复计入。

[工具图片请求投影](../src/main/agent/conversationContext.ts) 在发送模型、计算上下文和压缩时，将已有后续正常模型响应的工具图片替换为占位说明。原始图片及 artifact 始终保留在消息正文中；未处理图片、工具文本、调用 ID 和用户附件不变。压缩与重试不能截断待处理图片；主子 Agent 各自依据消息状态判断。

[工具结果文件](../src/main/agent/toolResultFile.ts)用于上下文溢出时的文本收缩：先将完整文本（结构化内容为 JSON）原子写入数据目录 `db/projects/<项目ID>/conversations/<主对话ID>/tool_results/`，再向本次模型请求提供绝对文件路径和首尾预览；不重跑工具，不修改持久的完整消息，待处理图片不走此收缩。文件按内容哈希命名，重复内容复用路径；写入失败则报错，不返回不存在的引用。它是会话持有的可读副本，不是第二份会话状态。同一主对话内按内容去重；文件纳入备份，随整个对话删除，清缓存或结束单轮运行不删除。读取沿用现有文件工具与权限；Shell、自定义工具等已有内联输出上限和受管输出查询机制保持不变。

编辑和重新生成从当前消息选择有效前缀。[NativeHistoryOwner](../src/main/agent/nativeHistoryOwner.ts) 在一次事务中替换当前根状态、截断相关运行和活动、处理移除的子线程并创建新运行输入，先等待受影响执行与清理真正退出。事务失败保留原状态；废弃附件进入持久清理队列，删除失败不撤销编辑或丢弃编辑草稿，重新打开会话时重试。资源清理完成、写入停止且数据库关闭后，删除整个会话目录及其 `tmp/conversations/<主对话ID>/`；目录删除失败仍保留 catalog 删除标记，可在重启后重试，部分删除不会使其他会话失效。

显式删除整个对话按 catalog 中的主对话 ID 定位，仅停止已有运行实例、关闭已打开的数据库，再删除其持久目录与临时目录，最后清除索引。不为删除创建运行实例，不读取或校验待丢弃的消息、附件引用或数据库版本；数据库缺失、损坏或无法读取均不阻止删除。实际文件删除失败时保留可重试的删除标记，不冒充删除成功。批量清理仍保留置顶、运行中和审批等待的对话，并检查可读会话中的未解决后台调用。

UI 按索引分页读取，run 活动初始窗口为末尾 100 条，先选窗口再解码正文。只合并连续分页区间，漏收实时事件形成的空段仍可补载；子 Agent 结果按需读取。模型轮次按数据库中的 run/Agent 索引计算，不随分页改变。界面和模型从相同的应用消息正文解码，模型请求再按所选协议投影。

备份通过 [SQLite backup API](../src/main/agent/agentDatabaseBackup.ts) 分别快照 catalog 和登记的会话库，不直接复制可能存在 WAL 的主文件。复制期间数据结构变更、附件删除和文件恢复材料维护排队，后台 Agent 可继续提交完整消息。会话文件仅按 catalog 快照中未删除的主对话清单收集；已接受删除或创建中断留下的未登记目录不进入备份，未登记的原文件仍保留在磁盘。恢复校验当前格式后，停止相关写入再切换数据目录。ZIP 中的 `anas-backup.json` 明确声明当前布局；旧备份在停止运行时和替换数据之前拒绝。新备份排除旧布局、全局缓存和临时目录。

文件批量修改的历史路径按记录自身的 Windows／POSIX 语义校验，保留原始文本和哈希；换平台读取历史或恢复备份不重新解释这些路径。对外部项目文件执行恢复、续跑或临时文件清理前，要求记录路径属于当前平台；不自动映射盘符或把另一平台的绝对路径当作本地相对路径。项目源码和外部目录仍需用户另行准备。

文件修改恢复材料按主对话隔离，当前对话及其子 Agent 共享同一 `FileEditStore`；正常收尾先将差异和内容归档进会话数据库，再清除不再需要的材料，崩溃恢复所需记录继续保留。`get_file_edit_diff` 的 retained 范围仍可发现其他对话保留的恢复记录，恢复工具按运行 ID 定位所属目录；已截断运行的材料从当前对话目录查找，不依赖旧目录。正在使用的恢复材料阻止所属对话被删除。SQLite WAL/SHM 与所属数据库同目录。消息编辑、方向附件等临时副本放在全局 `tmp` 下，可随启动、退出清理。文件补丁的 `.anas-patch-*.tmp` 仍位于目标文件旁，以保证同文件系统原子替换，由事务清理。

## 性能与验证

增量正文存储消除每步复制完整历史的读写放大，不保证对话占用固定空间。真实消息、工具输出、附件和产品记录随工作量增长；顺序比较、引用清理、新轮次完整还原及 SDK 请求编码仍有开销。SQLite 写入与部分解码仍在 Electron 主进程，窗口响应性需通过构建后的应用验证。

- 存储、引用和事务：[原生执行存储](../src/main/agent/nativeExecutionStore.test.ts)、[权威消息投影](../src/main/agent/nativeMessageProjection.test.ts)。
- 恢复及生命周期：[原生恢复](../src/main/agent/nativeRuntimeRecovery.test.ts)、[宿主释放与取消](../src/main/agent/nativeRunHost.test.ts)、[子任务投影](../src/main/agent/nativeSubagentProjection.test.ts)。
- 展示和清理：[活动分页](../src/main/agent/agentActivityWindow.test.ts)、[历史编辑](../src/main/agent/nativeHistoryRuntime.test.ts)、[后台清理](../src/main/agent/nativeBackgroundCleanup.test.ts)。
- [Electron 存储验收](../scripts/electron-current-storage.cjs)：`npm run test:e2e -- --storage-only` 使用隔离数据目录，在持续追加期间检查窗口交互、切换和分页；默认 1,000 条消息，可设 `ANAS_E2E_STORAGE_MESSAGES=10000` 检查 10,000 条规模。
- 启动响应性：`npm run test:e2e -- --startup-only` 检查环境探测及 Dev 统计未完成时的窗口交互。
- [运行中模型切换](../scripts/electron-model-selection.cjs)：`npm run test:e2e -- --model-selection-only` 使用隔离数据目录与本地模型服务，检查请求挂起时切换模型和预设、实时预算更新、后续请求参数及删除模型后的明确终止。

## 工具活动身份

工具活动以应用调用 ID 关联模型响应和结果，供应商调用 ID 可以重复。启动时可从原生调用记录、效果记录和已提交批次顺序重建 v1 活动索引，同时恢复子 Agent 投影和待审批关联；重建在事务内完成，不改写消息正文、不消费审批、不重放操作。缺少时间证据的重建活动不伪造起止时间。

摘要的 TypeScript 字段为 `committedRevisionId`。v1 数据库继续保留 `committed_checkpoint_id` 列名，其值为原生执行修订 ID；保留列名用于保护当前格式的已有数据，并不代表存在框架存储。
